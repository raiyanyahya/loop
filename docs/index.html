The loop, engineered.

Runs Claude Code, Codex, Gemini CLI or any agent again and again from one markdown file. It remembers between runs, checks every claim of “done”, asks a critic, reverts what doesn't measure up, and knows when to stop.

$ npm i -g loop-cli

Nothing to install yet? npx loop-cli demo runs a scripted agent through a real loop, no API key needed.

greet-lib — loop run

A bash loop is blind.

This is how people run agents overnight today. It works. It also forgets everything between runs, believes the agent when it says it is finished, never stops on its own, leaves no record, and lets the agent edit the tests that judge it.

$ while :; do cat PROMPT.md | claude; done
  • no memory the letter

    Each iteration ends by writing a note to the next one. The loop puts it at the top of the next prompt.

  • no verification until

    Done means a test passes, a checklist is complete, or both. A false claim is rejected with the failing output.

  • no brakes guards

    Iterations, hours, dollars, and a stall detector for loops that stop changing anything.

  • no record the journal

    Every prompt, output, changed file, and verdict, plus loop log and an HTML report to share.

  • blind trust critic, protect, revert

    A second agent judges the diff, the tests can't be edited, and a metric loop reverts anything that doesn't measurably win.

One file runs the loop.

A Loopfile is YAML for the loop and markdown for the agent. Humans read it, agents read it, and the loop re-reads it every iteration, so you can edit the goal or tick a box while it runs.

LOOP.md in your project
--- name: search-api
Shown in the terminal header and in every commit message.
agent: [claude, codex]
Two agents take turns: Claude builds, Codex reviews. A single name is fine too.
until: [checklist, "npm test"]
What done means. Every condition must hold: here, all boxes ticked and the tests green.
critic: codex protect: ["test/**", SPEC.md]
A second agent reviews the diff in a fresh session before “done” counts. Protected files are restored if the worker touches them.
memory: NOTES.md
Durable notes the agent keeps across loops. The letter is for the next iteration; this is for every future one.
max: 30 max_cost: 20 stall: 3
Brakes. Thirty iterations, twenty dollars, or three iterations in a row that change nothing.
git: true
Commit after each iteration, so nothing is lost and every step is diffable.
rituals: - every: 5 prompt: | Review all work so far as a strict reviewer. Fix what you find. ---
Every fifth iteration runs this instead of the goal.
# Goal Add full-text search to GET /posts. See SPEC.md.
The prompt. Plain markdown, handed to the agent every iteration along with the letter and the latest feedback.
# Checklist - [x] Migration: tsvector column and GIN index - [ ] q= query param, ranked results - [ ] Tests: ranking, empty query, injection - [ ] README section with examples
The agent ticks boxes as it goes. When they are all ticked and npm test passes, the loop ends.

Every iteration writes to the next.

Each iteration is a fresh session with no memory. So before it ends, the agent writes a short letter to its next self: what it did, what to do next, what to avoid. The loop puts the letter at the top of the next prompt. It is the only memory that survives, and it turns a pile of amnesiac runs into one continuous worker.

loop letter shows the current one.

Done is a claim. The loop checks.

An agent will say it is finished. The loop treats that as a claim: it runs the checks, defends the files the agent must not touch, asks a critic, and only then agrees. If the claim fails, the next iteration is told exactly why.

The agent claims done

On its own line, as the last thing it says.

│ Both functions pass. I believe the work is complete.
│ <loop:done/>

The loop verifies

Every until condition runs. Protected files are restored. In a metric loop, anything that didn't improve is reverted.

▸ check: node test.js → pass
▸ verdict: continue  done rejected: 1 checklist item still open

The critic judges

A separate session reads the goal, the diff, and the letter. It can veto.

▸ critic (codex)
│ <loop:reject>1. No test for the empty query.</loop:reject>

The next iteration knows

The rejection, the failing output, and the critic's reasons land in the next prompt, with a history of every attempt.

The loop rejected your last “done”
– 1 checklist item still open
– the critic rejected the work: 1. No test for the empty query.

The agent can talk back.

A handful of tags, written in plain text on their own line, let the agent steer its own loop. Because they only count at the start of a line, the agent can talk about them without triggering them.

the agent writeswhat happens
<loop:done/>The loop verifies the claim against every until condition and ends if they hold.
<loop:stuck>why</loop:stuck>The loop stops and shows the reason. Fix what it needs, then loop run continues with the letter intact.
<loop:ask>question</loop:ask>In a terminal, you are asked right there. Unattended, the loop parks itself; loop answer "..." and loop run resume it with your reply in the prompt.
<loop:handoff>codex</loop:handoff>The next iteration runs on a different agent.
<loop:sleep>10m</loop:sleep>Wait before the next iteration, for example while a deploy settles.
<loop:note>text</loop:note>Leave a note in the journal for whoever reads the log later.
<loop:approve/> <loop:reject>why</loop:reject>The critic's verdict. A rejection blocks “done” and its reasons feed the next iteration.

Loops come in shapes.

loop init asks what kind of loop you want: finish, optimize, maintain, or research. Each template is a few lines of frontmatter you can read in full.

Relay

Two agents alternate. One builds, the other reviews the diff and tightens the tests, until both agree and the suite is green.

agent: [claude, codex]
until: [done, "npm test"]

Overnight

No “done” at all. Eight hours, a commit per iteration on its own branch, and a review ritual every fifth run.

until: never
max_time: 8h
git: { commit: true, branch: loop/overnight }

Fix the build

Green is done. No claim from the agent needed; the loop ends the moment the command exits 0.

loop run -p "Make CI pass. Fix root causes." --until "npm test"

Optimize

One experiment per iteration. The loop measures, keeps the change only if the number improves, and reverts the rest with a note of what was tried.

metric: "node bench.js"
direction: min
keep: improve

Plan, then build

Iteration one only plans. Then one checklist item per iteration, tests protected, notes kept, and a critic before done.

rituals: [{ at: 1, prompt: "Plan. Do not code." }]
protect: ["test/**"]
critic: same

Not code at all

Deepen a report a little each iteration, with a checklist for outline, sources, counterarguments, and a final edit.

until: checklist
max: 12

Works with the agents you already have.

Each one runs in its non-interactive mode with permissions bypassed, because that is what a loop is for. Run loops in a container, a VM, or a repository you can afford to reset.
